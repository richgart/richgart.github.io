The method, in miniature

Workshop talk goes in, sourced requirements come out. Hover or tap an item on the right to see the exact words it came from. This is invented sample text, not client data.

Before: raw transcript

…so yeah, the order form. Dana said reps keep re-entering the same address twice, we'd want that to prefill from the account. Oh, and legal needs the contract term shown before submit, it can't be hidden. Mark's worried about the Q2 date, it depends on whether the billing API is ready. Someone should check on that. Anyway, on discounts, anything over 15 percent goes to a manager for approval…

After: structured output

  • Requirement Prefill the order form address from the account.
  • Requirement Show the contract term before submit.
  • Requirement Discounts over 15% need manager approval.
  • Risk Q2 date depends on billing API readiness.
  • Action Check billing API readiness. No owner named: a human reviewer assigns one.

How I work

  • Verify everything. Every AI output I ship traces back to a source quote and gets checked against a second pass.
  • Keep a human in the loop. The people closest to the work review the output, so they trust it and own it.
  • Teach, then step back. I write the guides, templates, and FAQs so a team can run it without me.
  • Start where the program is behind. I tend to land on programs where everyone needed everything yesterday, and I start by rebuilding trust.
